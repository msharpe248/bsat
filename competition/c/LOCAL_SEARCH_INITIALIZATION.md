# Clause-based local-search initialization

Each walk restores an assignment from saved phases and root values, then rebuilds
its clause counts and flip scores. Previously, after counting true literals by
clause, score initialization walked every variable's positive and negative
occurrence lists and revisited clause counts for each literal.

The new initializer accumulates the same break-minus-make score while counting
true literals. An unsatisfied clause subtracts one from every variable in the
clause; a clause with one true literal adds one to that variable; a clause with
multiple true literals contributes nothing. The existing normalized-clause
invariant makes those contributions exact. Unsatisfied clauses need a second
literal pass, but the full occurrence-list pass is removed. No additional memory,
option, or heuristic change is introduced. Occurrence lists remain in use for
incremental flip updates.

## Verification

All 24 C suites pass in release and ASan/UBSan builds. The score regression now
covers all 16 initial assignments of its four-variable formula, bringing it to
1,788 checked prefixes, including its long-clause cases. The separate 2,040-prefix
scan oracle still checks assignment and RNG equivalence, unsatisfied counts, and
prefix-tree invariants. Independent validation passes 416 model/proof checks per
build. Both builds pass 36 short-deadline cases; maximum observed CPU overrun is
0.003 seconds in release and 0.042 seconds in debug. These deadline cases do not
prove a worst-case bound for every initialization.

The standalone driver accepts an optional final argument, the number of walk
runs. It reuses the state, starting each run from solver phases while retaining
the RNG state, and prints total flips, run count, and summed final unsatisfied
counts. Only its final result is emitted as SAT or UNKNOWN; any emitted SAT model
is checked. Omitting this argument preserves the original one-run behavior.
CI and local smoke checks cover three zero-flip initializations of a root-satisfied
formula in both builds. The [planted comparison](benchmark_results/walk-init-planted-20260907.json)
checks six fixed formulas with three seeds: both versions return 18/18 verified
SAT models with identical flip counts.

## Initialization measurements

Baseline is `f3e8f56`; both versions use the extended driver. Four fixed inputs
were run three times per version with 1,000 zero-flip walks each. The two random
3-SAT inputs with contradictory cores are generated by
`tests/generate_walk_selection_corpus.py`; the other two are the recent battleship
and belpyramid competition development inputs. All inputs and executable hashes
are recorded in the [raw comparison](benchmark_results/walk-init-isolated-20260907.json).

The internal walk CPU measurement includes repeated phase restoration, score and
clause initialization, and prefix-tree construction. It excludes parsing and
state allocation. The same phase assignment is repeated, so this is a warm-cache
initialization measurement, not a full search simulation. Runs are serial and
separate from builds and validation.

| Input | Occurrence median CPU | Clause median CPU | Speed ratio |
| --- | ---: | ---: | ---: |
| Random 3-SAT, 1,000 variables | 0.023558 s | 0.019912 s | 1.18x |
| Random 3-SAT, 10,000 variables | 0.377373 s | 0.223744 s | 1.69x |
| Battleship `ed6d842f` | 0.020548 s | 0.015317 s | 1.34x |
| Belpyramid `5831f356` | 0.568664 s | 0.371589 s | 1.53x |

Each run performs exactly 1,000 initializations and zero flips, and every matched
input has the same summed unsatisfied count. All these deliberately zero-flip
walks return UNKNOWN; their PAR-2 summaries do not measure solver quality and
should not be used as speed evidence.

From the repository root, generate and measure a candidate:

```sh
python3 competition/c/tests/generate_walk_selection_corpus.py /tmp/bsat-walk-selection-corpus
make -C competition/c local-search-benchmark MODE=release
python3 competition/c/tests/benchmark.py \
  --solver 'clause=competition/c/bin/local_search_benchmark_release {input} 0 1 1000' \
  --manifest /tmp/bsat-walk-selection-corpus/manifest.json \
  --repeats 3 --timeout 60 --output /tmp/walk-init.json
```

## Full-solver measurements

The four recent development targets use VMTF, trail reuse, local search every
5,000 conflicts and 1,000 flips per attempt. Each is run three times per version
with ten solving CPU seconds and fifteen wall seconds. SAT models and UNSAT
proofs are independently verified outside timing. Results are recorded in the
[full-solver comparison](benchmark_results/walk-init-hybrid-20260907.json).

| Target | Occurrence median process CPU | Clause median process CPU |
| --- | ---: | ---: |
| hamiltonian `a497d784` | 0.483623 s | 0.584370 s |
| multiplier-circuits `90bec6dc` | 0.655306 s | 0.659185 s |
| belpyramid-puzzle `5831f356` | 3.012428 s | 2.857478 s |
| battleship `ed6d842f` | 0.816072 s | 0.907598 s |

Both implementations certify 12/12 runs, with zero errors. All non-timing
statistics match across paired runs, including conflicts, propagations, decisions,
local-search calls/wins, and literal inspections. Mean wall PAR-2 is 2.0160 versus
2.0572 seconds; wall timing is noisy. The selected targets establish no additional
solves. The initialization gain alone does not justify retaining a full-solver
regression; the seven-repeat confirmation below checks whether it persists.

The [seven-repeat confirmation](benchmark_results/walk-init-confirmation-20260907.json)
uses the same binaries, inputs, options and limits. It was run because the first
batch showed apparent CPU regressions on battleship and Hamiltonian.

| Target | Occurrence median process CPU | Clause median process CPU |
| --- | ---: | ---: |
| multiplier-circuits `90bec6dc` | 0.815980 s | 0.806258 s |
| belpyramid-puzzle `5831f356` | 3.019743 s | 2.961703 s |
| battleship `ed6d842f` | 0.913777 s | 0.905989 s |
| hamiltonian `a497d784` | 0.594439 s | 0.595678 s |

Both versions certify 28/28 runs with no errors and identical non-timing search
statistics. The earlier large median regressions do not repeat; CPU medians are
close, with Hamiltonian essentially unchanged. Mean wall PAR-2 changes from
2.1844 to 1.9903 seconds, but the difference and substantial wall-time variation
should not be treated as a reliable general throughput gain. Both batches are
retained rather than selecting the more favorable one.

Retain the simpler initializer for the directly measured initialization savings
and preserved search behavior. No additional solves or competition-wide speedup
is established, and local search remains off by default.
